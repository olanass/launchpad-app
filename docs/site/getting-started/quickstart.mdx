## Publish your API

1. Open [Olanas](https://olanas.xyz) and select **Launch API**.
2. Connect the creator wallet. The website uses this wallet as the listing's payout address.
3. Enter your project name, description, category, and public HTTP or HTTPS endpoint. Enable only the methods your API supports.
4. Choose the price per request and a currency offered by the deployment. The launch form selects USDG by default when available.
5. Add a logo or demo video if useful. Upload an OpenAPI 3.0 or 3.1 JSON document to help agents understand your API's operations and inputs.
6. Review the listing and sign the creation message. Publishing authenticates the listing with a wallet signature; it is not a buyer payment.
7. Save the resulting gateway URL and check the project in **Explore**. Use **My projects** to review and manage your listings.

Your API must already be hosted and reachable. Localhost and private-network destinations are rejected. Olanas forwards paid requests to your endpoint; it does not host your application code.

For endpoint paths and schema details, read [Publish an API](/developers/overview).

## Discover an API

Open **Explore** on [the website](https://olanas.xyz), or connect an agent to the remote MCP endpoint at `https://olanas.xyz/mcp`.

An agent uses `search_apis` to find live listings and `get_api_details` to inspect the selected service. Check the method, operation path, input schema, accepted currency, and price before preparing a request.

## Make a human-approved agent request

1. Choose a service and prepare its exact request input.
2. Call `new_order_identity` once and save the returned request ID and private access token.
3. Call `create_order` with those identifiers, the service slug, method, relative path, and body.
4. Open the returned private approval link. Review the input and quote, sign the order approval, and confirm the payment in your wallet.
5. Let the order verify the submitted transaction and execute the API request.
6. Use `get_order` to retrieve the saved result. Use `reconcile_order` to check the original submitted payment when confirmation or delivery is still pending.

Keep the same identifiers when recovering an interrupted order. A new request ID means a new intended purchase.

## Enable local agent payments

For requests without a browser approval on every purchase, install the local wallet companion and enable an owner-controlled spending session. Follow [AI agents and MCP](/developers/agents). Connecting only the website MCP server does not enable autonomous payments.

## Before paying

The current website uses **Robinhood Chain mainnet (4663)**. Fund the paying wallet with the listing's payment asset and ETH for network fees. Review the quoted recipient and amount. Payment confirmation and API success are separate: an upstream API can return an error after a valid payment.

For integration work without spending funds, use the repository's isolated automated tests. This website does not offer a testnet network selection.
