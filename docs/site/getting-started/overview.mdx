title: "What is Olanas?"
description: "A launchpad connecting API projects with AI agents and pay-per-request usage."
---

Olanas helps projects turn existing APIs into paid services that humans and AI agents can discover and use. Builders keep running their own endpoints, while Olanas supplies the listing, discovery interface, payment requirement, verification, and request delivery.

## Who uses Olanas?

| User | What they do |
| --- | --- |
| API project builders | Publish an endpoint, describe its inputs, choose a price, and receive payments. |
| AI agents | Discover services, prepare requests, and retrieve results through MCP or HTTP. |
| Agent owners | Approve individual purchases or configure bounded local-wallet spending sessions. |

Examples of useful projects include market data, onchain data, research, and document processing APIs. These are use cases, not a promise that a particular service is listed.

## What a project launches

A listing includes a name, description, category, allowed HTTP methods, price, currency, and payout address. It can also include a logo, demo video, and OpenAPI document.

The published gateway has the form `/x402/:slug`. Public metadata exposes this gateway instead of the configured upstream endpoint. Keeping an endpoint out of the catalog is not a substitute for securing the project's own server.

## What Olanas does

- Makes live listings searchable in Explore and available through machine-readable discovery.
- Exposes MCP tools for discovery, request preparation, order status, and payment-proof calls.
- Binds a durable order to a specific request and quoted payment.
- Checks confirmed onchain payments before executing paid requests.
- Stores durable-order responses and records usage and payment information.

## What the project operates

The builder hosts the API, maintains its uptime, defines its input and output contract, and handles the service's own data and behavior. Olanas does not deploy the project's source code or guarantee the correctness of third-party results.

## Two ways to authorize agent payments

**Human-approved orders:** an agent prepares an order and gives its owner a private approval link. The owner reviews the request and quote, signs approval, and confirms payment.

**Local wallet companion:** the owner enables a session with spending limits and allowed services. The local signer can approve eligible purchases within that policy. The website's remote MCP endpoint alone cannot sign payments.

See [AI agents and MCP](/developers/agents) for setup and recovery rules.

## Related features

[Sell files](/ecosystem/content-payments) provides payment links for downloadable files or text. The [OLANAS token](/token/utility) is a supported API payment option when selected by the project. Neither file sales nor token ownership is required to publish a listing priced in another supported asset.
