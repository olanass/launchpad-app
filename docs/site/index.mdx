Olanas is an **x402 API launchpad**. Projects publish their APIs on Olanas, choose a price per request, and make them discoverable to AI agents. Agents find a service, inspect its inputs and price, authorize payment, and receive the API result.

**Publish an API. Get discovered. Get paid when it is used.**

## For project builders

Bring an existing HTTP API to **Launch API** on [the Olanas website](https://olanas.xyz). Add your project details, endpoint, supported methods, payment currency, and price. Sign the listing with your wallet.

Olanas provides the public listing, paid gateway, discovery metadata, and payment verification. Your project continues to host and operate the API.

[Launch your first API](/getting-started/quickstart)

## For AI agents and their owners

Agents discover live services through the catalog or MCP, inspect the request schema, and prepare a paid request. The owner can approve an order in a browser, or enable a bounded spending session in the local wallet companion.

Payment is verified before Olanas forwards the request to the project's endpoint. The durable-order flow saves the result so the agent can retrieve it without buying the same request again.

[Connect an agent](/developers/agents)

## The request lifecycle

| Step | What happens |
| --- | --- |
| Discover | Find a live API and inspect its inputs, methods, and price. |
| Request | Prepare the exact API operation and receive its payment requirement or order quote. |
| Pay | An authorized wallet sends the required asset to the project's payout address. |
| Receive | Olanas verifies payment, calls the API, and returns the result. |

## Network and payment support

The application currently supports **Robinhood Chain mainnet, chain ID 4663**. ETH, USDG, and OLANAS are configured payment assets; each API listing specifies the currency it accepts. Additional assets depend on the deployment configuration. Check the [network reference](/developers/network) and the actual quote before paying.

The current payment implementation uses x402 v2-shaped challenges with the `onchain-tx` scheme for confirmed transfers. Integrations must support that scheme; support for another x402 scheme does not automatically make a client compatible.

**Sell files** is also available for paid downloads. It is a separate workflow from publishing and calling APIs; see [Sell files](/ecosystem/content-payments).
