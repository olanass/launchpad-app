## API launchpad

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/api/services` | Create a wallet-signed paid API listing |
| `GET` | `/api/services` | Browse, search, and filter listings |
| `GET` | `/api/services/:slug` | Read public service metadata and analytics |
| `GET` | `/api/services/creator/:address` | List services owned by a creator wallet |
| `GET` | `/api/services/:slug/logo` | Read the uploaded service logo |
| `GET` | `/api/services/:slug/openapi.json` | Read the optional gateway-rewritten OpenAPI document |
| `GET` | `/api/services/:slug/health` | Check the configured upstream endpoint |
| `PATCH` | `/api/services/:slug` | Wallet-signed update, pause, or resume |
| `DELETE` | `/api/services/:slug` | Wallet-signed listing deletion |
| `GET` | `/discovery/resources` | Discover live paid APIs and payment requirements |
| `GET/POST/PUT/PATCH/DELETE` | `/x402/:slug/*` | Invoke a paid API using an allowed method |

## Agent interfaces

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/mcp` | Stateless Streamable HTTP MCP server with discovery, call, balance, and receipt tools |
| `GET` | `/llms.txt` | Combined AI-readable product and developer documentation |
| `GET` | `/docs/:page.md` | Raw Markdown for one documentation page |

The Markdown homepage is `/docs/home.md`; `/docs` serves the browser interface. Remote MCP tools are listed in [AI agents and MCP](/developers/agents).

## Durable API orders

Private order routes use `Authorization: Bearer <accessToken>`. Generate and retain a random access token and stable request ID before creation. Do not place the bearer token in a public URL or log.

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/orders/network` | Public network and payment-asset configuration |
| `POST` | `/api/orders` | Prepare one request and its quote |
| `GET` | `/api/orders/:id` | Read private status and saved result |
| `POST` | `/api/orders/:id/approval-message` | Obtain the canonical message for the proposed payer |
| `POST` | `/api/orders/:id/approve` | Submit the wallet's order approval signature |
| `POST` | `/api/orders/:id/payment` | Attach the original submitted transaction hash |
| `POST` | `/api/orders/:id/reconcile` | Verify that payment and finish eligible execution |
| `POST` | `/api/orders/:id/reject` | Reject a request through the review flow |
| `POST` | `/api/orders/:id/refresh` | Refresh an eligible quote |
| `POST` | `/api/orders/:id/reopen` | Explicitly reopen an eligible rejected order |
| `POST` | `/api/orders/:id/cancellation-message` | Obtain a message for cancelling an unpaid approval |
| `POST` | `/api/orders/:id/cancel-approval` | Submit the approving wallet's cancellation assertion |

Creation, approval, payment submission, and execution are separate operations. State restrictions apply; a submitted transaction cannot be replaced by calling these endpoints. See [Payment flow](/developers/payment-flow).

## Paywalls

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/api/paywalls/create` | Create a signed text or file listing |
| `GET` | `/api/paywalls/:id` | Read public listing metadata |
| `GET` | `/api/paywalls/creator/:address` | List a creator's public listings and totals |
| `GET` | `/api/paywalls/:id/download` | Receive a 402 challenge or download after verification |
| `GET` | `/api/paywalls/gas-estimate` | Request an RPC-backed gas estimate |

## Facilitator

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/facilitator/supported` | List configured assets and payment schemes |
| `POST` | `/facilitator/verify` | Verify a proof without recording settlement |
| `POST` | `/facilitator/settle` | Verify and persist a durable receipt |
| `GET` | `/facilitator/receipts/:id` | Retrieve a settlement receipt |
| `GET` | `/facilitator/analytics` | Read facilitator ledger analytics |

## Browser configuration

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/privy/config` | Return public login and selected-network configuration |
| `GET` | `/api/services/networks` | List enabled launchpad networks and payment currencies |

<Note>
  Legacy email-only wallet creation routes return `410`. An email address is not authentication, and the application does not invent wallet addresses.
</Note>

## Production storage

The API catalog, orders, saved results, logos, receipt reservations, payment redemptions, and usage analytics use durable database storage. Configure `TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN` before deploying the launchpad.
