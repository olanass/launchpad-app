How payments work

Create a paywall

Connect your wallet, upload a file or enter text, and choose a price in a configured currency. Sign the listing in your wallet to publish. Cancelling the signature cancels publication.

Pay and download

The buyer sends the listed amount in the listed currency to the creator. As soon as the transaction is confirmed, the server verifies the transfer and releases the file.

If a request times out, retry in the same tab. The existing transaction is checked again. Confirmed payments can be retried for the same file without another charge.

Storage and privacy

Files are encrypted in the server vault. Public previews show file metadata only. Files are not shared through browser P2P. Retention depends on the operator's storage and backups.

Wallets and fees

Browser wallets are supported. Embedded login requires the operator to configure Privy. Gas varies with the network. Transfers go directly to the creator; this implementation does not collect a platform fee.

Developer integration

This application uses a custom HTTP 402 challenge and payment proof format. It is not a certified implementation of the standard x402 protocol. See the project README for configuration and proof examples. Signed voucher demonstrations are available only in explicit demo mode and never move funds.
